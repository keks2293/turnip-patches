CCU 2D read == write: 56/56 steady windows, max |diff| 0.  The XML names selectors 10
and 11 separately, and the block does program distinct counters (GMEM read and write
differ by 4x in cfg-vertex dumps), so the two are indistinguishable here: either one
selector aliases the other, or both count CCU requests of either direction.  Their
value is 5.0 M/s, 96% of the CMP read+write request count in the same windows
(5.2 M/s), which is a 3D-path rate and not a blitter's - so these are not the 2D
engine's counters and cannot tell a 2D copy from a 3D one, which is what the cfg
header wanted them for.  A write-only 2D op would separate them; nothing here can.
