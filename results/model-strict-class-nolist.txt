# The strict class rule for a no-list MUTABLE image, all 23 Vulkan classes
#
# Question: upstream's `TODO: limit based on compatiblity class` (tu_image.cc) says
#           the refusal of a MUTABLE image created WITHOUT a format list could be
#           narrowed by the compatibility class instead of being absolute.  Which
#           classes would a strict reading grant on a7xx_gen2 - the whole class, and
#           the class minus the members the driver cannot lay out at all?  And what
#           changes once the one pair of compat labels that the XMC probe measured is
#           folded (journal 32, results/test-xmc-64bit-compat.log)?
# Method:   scripts/fmt-list-gate-check.py --strict-class.  The predicates are a
#           Python port of ubwc_possible() (tu_image.cc), fd6_ubwc_compat_mode()
#           (freedreno_ubwc.h, with the 0006/0011/0012 rows) and of the refusal of a
#           missing list in format_list_ubwc_possible() and
#           tu6_mutable_format_list_ubwc_compatible().  A model, not a measurement:
#           nothing ran on the GPU and no line here says what the chip does.  The
#           last block is the one place a measurement enters, and it names which
#           pair it measured (fold_64(), the mirror of the knob in experiments/exp-22).
# Inputs:   tests/vk-fmt-classes.json (generated from vk.xml and vk_format.c, see its
#           own provenance field); src/freedreno/fdl/fd6_format_table.c of the Mesa
#           tree at base 6dfa32a - no patch of this stack touches that file, so a
#           format it does not name is a gap upstream, not a gap of ours;
#           GEN2_PROPS in the script, read from freedreno_devices.py for
#           [a7xx_base, a7xx_gen2].
# Read:     a class is GRANTED when every member the rule counts passes
#           ubwc_possible() and agrees on one compat mode.  A "no table row" line
#           names the members with no texture format in fd6_format_table.c: a view in
#           one is broken whatever this rule answers, so the third and fourth blocks
#           repeat the question with those members excluded - the difference between
#           the rule as it reads and the rule as it could be written.
# Volume:   this file says nothing about bytes.  The no-list volume of each class is
#           in journal 28; a granted class with 0 MiB in the game is a correctness
#           result, not a performance one.
# Not here:  the vkd3d and zink lists this tool also prints.  Run
#           scripts/fmt-list-gate-check.py without --strict-class for them; their
#           narrative is journals 16 and 21.
# Regenerate:
#           python3 scripts/fmt-list-gate-check.py --strict-class
#
GPU properties: FD740 = [a7xx_base, a7xx_gen2] -> {'ubwc_unorm_snorm_int_compatible': True, 'ubwc_all_formats_compatible': False, 'has_8bpp_ubwc': False, 'supports_uav_ubwc': True}

fd6_format_table.c gives a texture format to 245 pipe formats; 50 of the formats in vk-fmt-classes.json have none.
